## Current Project: Iterative Plan Generation for Test-Time Compute Scaling

### Project Goal

Test the hypothesis that **structured plans** can make non-reasoning models perform as well as reasoning models while using significantly fewer tokens.

### Mathematical Formulation

Let:
- $r$ = ground truth response to mathematical query $q$
- $p_\theta$ = non-reasoning LLM (e.g., `gpt-52--none`)
- $p$ = reasoning model (e.g., `gpt-52` with reasoning enabled)
- $t$ = reasoning trace (CoT)
- $s_p$ = structured plan generated by our agents

**Hypothesis**: We want to test if there exists $s_p$ such that:
- $p_\theta(r|q, s_p) \geq p(r|q, t)$ (accuracy comparable or better)
- $\|s_p\| << \|t\|$ (plan much shorter than reasoning trace)

### Why This Matters

Reasoning models waste tokens on inefficient exploration. By systematically generating high-quality, compact reasoning plans upfront, we can guide cheaper non-reasoning models to achieve similar performance at lower cost.

## Implementation Plan

### Agents Being Built

We're implementing two complementary approaches for generating structured plans:

#### 1. Sequential Refinement Agent
- **Concept**: Start with initial plan, iteratively critique and refine up to `max_refinements` times
- **Workflow**:
  1. Generate initial plan
  2. Loop (up to `max_refinements`):
     - Critique current plan
     - Decide: STOP or CONTINUE
     - If CONTINUE: generate refined plan
  3. Output final refined plan
- **File**: `src/matharena/solvers/sequential_plan_refinement_agent.py`
- **Config**: `configs/agent_scaffolds/sequential_plan_refinement.yaml`
- **Issue**: [#1](https://github.com/shivchander/matharena/issues/1)

#### 2. Branching Exploration Agent
- **Concept**: Branch at decision points to explore multiple paths, then synthesize into one plan
- **Workflow**:
  1. Generate initial plan
  2. When model identifies decision points, branch into parallel explorations
  3. Build tree up to `max_branches` depth
  4. Collect all leaf plans
  5. Use LLM to synthesize one unified plan
- **Branching format**:
  ```
  PLAN: [plan text]
  BRANCH_POINT: [description of uncertainty]
  OPTIONS: [Option 1 | Option 2 | Option 3]
  ```
- **File**: `src/matharena/solvers/branching_plan_exploration_agent.py`
- **Config**: `configs/agent_scaffolds/branching_plan_exploration.yaml`
- **Issue**: [#2](https://github.com/shivchander/matharena/issues/2)

### Integration with Existing Pipeline

Both agents output structured plans that feed into conditioned solvers:

**Current pipeline**:
- `PlanTournamentAgent` → generates K plans in parallel → tournament selection → best plan
- `ConditionedSolverAgent` → loads best plan → generates M solutions conditioned on plan → selects best

**New pipeline**:
- `SequentialRefinementAgent` OR `BranchingExplorationAgent` → generates refined plan
- `ConditionedSolverAgent` → generates solutions from that plan

### Future Enhancement

**Completion-based conditioning** ([Issue #3](https://github.com/shivchander/matharena/issues/3)):
- Current: Plan prepended in user prompt
- Proposed: Plan inserted as assistant context (treats plan as model's own reasoning)
  ```python
  [
    {"role": "user", "content": problem},
    {"role": "assistant", "content": f"Plan: {plan}\n\nNow solving:"},
  ]
  ```

## Experimental Evaluation

### Models

- **$p$**: `gpt-52` (or `gpt-5.2--xhigh`) - reasoning enabled
- **$p_\theta$**: `gpt-52--none` (or `gpt-5.2--none`) - reasoning disabled
- Same base model, controlled comparison

### Evaluation Protocol ([Issue #4](https://github.com/shivchander/matharena/issues/4))

1. **Filter dataset**: Find problems where $p$ succeeds but $p_\theta$ fails
   - These are "reasoning-benefiting" problems
   - Script: `scripts/filter_reasoning_benefiting_problems.py`

2. **Generate plans**: Run both agents on filtered problems
   - Sequential refinement with k=4, k=8
   - Branching exploration with d=3, d=4
   - Use both `gpt-52` and `gpt-52--none` to generate plans

3. **Conditioned evaluation**: Run $p_\theta$ with generated plans
   - Measure accuracy improvement

4. **Analysis**: Compare configurations
   - Baseline: $p_\theta(r|q)$ (no plan)
   - Reasoning: $p(r|q, t)$ (with reasoning)
   - Sequential: $p_\theta(r|q, s_p^{seq})$
   - Branching: $p_\theta(r|q, s_p^{branch})$

5. **Metrics**:
   - Accuracy (% correct)
   - Token count (plan + solution tokens)
   - Cost (tokens × pricing)

6. **Visualization**: Plot accuracy vs tokens, accuracy vs cost

### Success Criteria

Hypothesis is supported if:
- $p_\theta$ + structured plan achieves comparable accuracy to reasoning model
- Total tokens (plan generation + solution) << reasoning model tokens
- Cost efficiency improves

## Implementation Notes

### Code Patterns to Follow

Look at existing agents for patterns:
- **[best_of_n_agent.py](src/matharena/solvers/best_of_n_agent.py)**: Parallel generation, tournament selection
- **[plan_tournament_agent.py](src/matharena/solvers/plan_tournament_agent.py)**: Plan generation and tournament
- **[conditioned_solver_agent.py](src/matharena/solvers/conditioned_solver_agent.py)**: Loading upstream plans, conditioned solving

### Key Design Principles

1. **Checkpointing**: Use `_save_checkpoint()` / `_load_checkpoint_if_exists()` at each major phase
2. **Cost tracking**: Track per-step costs with `_query_with_cost()`, aggregate in history
3. **Parallel execution**: Use `ThreadPoolExecutor` for parallel generation/judging
4. **Jinja2 templates**: Store prompts in scaffold configs, render with `Template()`
5. **Structured parsing**: Use regex to extract structured outputs (CRITIQUE, DECISION, etc.)
6. **History logging**: Log each step with `_add_history()` including conversation, costs, metadata

### Testing Strategy

1. **Start small**: Test on 1-3 problems from `aime/aime_2025`
2. **Verify checkpointing**: Interrupt mid-run, resume, check it continues correctly
3. **Check costs**: Ensure token counts match actual API usage
4. **Validate parsing**: Ensure structured outputs are correctly extracted
5. **Test edge cases**: No refinements needed (early stop), no branch points, max depth reached
